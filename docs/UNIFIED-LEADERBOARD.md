# 两项任务的统一展示

同一个页面以“分类 + 高程”的联合准确率为主榜，同时提供旧的独立分类任务准确率。联合任务内部的分类准确率仅放在模型详情，并明确标注来源。

展示构建只读取已冻结结果，不调用模型、不修改抽取器，也不改变历史分数。它核验输入哈希、全部坐标、面积权重和分类标签，默认按完整模型名称连接结果，并应用明确确认的名称映射。用户已确认 Seed 2.1 的 0915 和 0902 是同一模型，因此统一为 Seed 2.1 一行：联合任务使用 0915，独立分类任务使用 0902。每个任务的 `source_model`、原始响应文件名及哈希分别保留，不合并分数或覆盖原始记录。

```bash
# 默认使用仓库自带的 results/2026-10-11 两项结果。
lwb verify
lwb build
lwb serve --directory dist --port 8732

# 也可显式组合两份已封存的结果包。
python -m land_water_bench.unified \
  --terrain results/2026-10-11/terrain \
  --classification results/2026-10-11/classification \
  --output dist-unified
```

`--terrain` 需指向完整且已封存的 `terrain_global_collection` 导出目录。`--classification` 使用公开分类结果包。输出目录必须不存在，构建会生成两任务分开的指标和响应文件、来源哈希、报告、验证回执及文件校验清单。GitHub Pages 等静态托管可直接使用该目录。

主榜保留联合 ±500 m、高程 MAE、独立分类准确率、联合任务覆盖率。页面依次是：排行榜；容差曲线与实时排名；三维“模型脑中的地球”（地形 / 误差尖刺）；拖动分界线的 A / B 对比地图与坐标详情；“海水退去”与八个高程档矩阵；方法说明。页面只展示结果，不再显示重试恢复、重新抽取或版本合并等过程信息，这些仍保留在 `data.json`、`RESULTS.md` 和各结果包里。

构建会额外生成 `atlas.json`（只用于展示，不改变任何成绩）：

- `tolerance_curve`：±100 m 到 ±2,000 m、每 100 m 一档的面积加权联合准确率，规则与官方评分完全一致（无效计错、未决剔除、只在有高程参考的点上计分）。构建时会把 ±100 / 500 / 1,000 m 三档与已封存成绩逐一比对，不一致即拒绝构建。
- `grid`：每个模型 16,200 个点的原始高程与状态（S / W / I 无效 / U 未决），供地图和三维地球直接绘制；原始回答正文仍按需从 `terrain-*.details.json` 读取。
- `profile`：海底起伏（相邻海洋格子的平均高差）、整百 / 整五百 / 整千取整比例、不同取值数、误差超过 2 km 的点数，以及 100 m 分箱的高程取值直方图。

三维地球使用打包在 `web/unified/vendor/` 里的 three.js r186 子集（MIT），生成方法见同目录的 `README.txt`。浏览器不支持 WebGL 时，页面其余部分照常可用，地球位置显示提示文字。

```bash
python scripts/check_unified_browser.py \
  --url http://127.0.0.1:8734/ \
  --output runs/unified-browser-check
```

浏览器检查逐行对照两任务指标和容差曲线，检查滑块的 20 个离散档位与实时排名、三个 WebGL 地球（渲染、切换模型、误差模式、点选、拖动、暂停与减少动态效果）、对比地图的分界线和各图层像素颜色、A / B 分歧计数、慢请求与加载失败隔离、原始回答、参考掩码、“海水退去”五个步骤、窄屏布局和私有路径隔离。在无头环境中运行时 WebGL 由 SwiftShader 软件渲染。

公式大括号、重复答案、明确更正、解释中的类别词及内容过滤的修订使用独立的[离线重算工具](REEXTRACTION.md)。统一展示的 `data.json` 在 `sources` 中记录来源采用的抽取版本与修订状态。仅合并旧结果不会更改其历史分数。
