# 未决请求的追加恢复

恢复使用新的运行目录，旧批次及其文件校验清单保持不变。仅把原来 `infra_error` 的点重新加入队列；有效回答、普通格式错误和输出截断均不重跑。

```bash
python -m land_water_bench.recover \
  --source runs/original-model \
  --output runs/recovered-model \
  --additional-timeout-retries 5
```

准备器验证原始哈希，按原始字节保留其余回答，并完整继承尝试日志。模型、题面、参考、输出上限、推理配置及累计限流预算不变；新增额度写入 `RECOVERY.json`。当前工具面向已封存的全球高程运行。

随后使用同一模型连接和原始运行参数续跑新目录，仅把 `--max-timeout-retries` 改成原值加上追加额度。例如，原值 2 加 5 后为 7，最多累计经历 8 次读取超时。原来已发生过读取超时的点，会沿用 600 秒时限；累计尝试数不会归零。断点恢复继续消耗同一份预算。

HTTP 400 内容过滤、HTTP 406 等非普通可重试错误会重新提交一次原请求；若再次返回终态错误，继续保留未决。不会为获得答案而更换题面、绕过过滤或重试已有普通错答。

恢复完成后，`recovery_results` 会检查新请求仅涉及所选点、旧尝试日志保持原前缀、非选中回答不变，再独立核验新分数并生成新版本结果。旧的独立分类任务的三条未决通过同一直接调用框架恢复，原始请求和累计尝试也保留。

页面恢复期间显示原成绩快照和追加恢复进度。全部恢复任务结束并通过校验后，自动切换到新结果，保留正在查看的模型与坐标。新返回的无效回答按原规则计错；仍未决的请求继续排除并报告覆盖率。
